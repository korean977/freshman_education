# 52-R1 프로젝트 소스 기반 보호·개방 로직

사용자가 제공한 `52r1.src`를 이번 보호 동작 변경의 기준으로 삼는다. 계전기 실물에서 읽거나 실행한 결과가 아니라, 업로드된 소스를 교육용 모델로 옮긴 결과다. 프로젝트 원본은 저장소에 게시하지 않았다.

## 확인 방법

- `LGIS PADT V0.11a SRC / G2K_FI SOURCE` 파일의 PKWARE DCL 스트림을 zlib 공식 contrib/blast로 해제했다.
- 심볼 블록 29,216바이트에서 166개의 레코드를 확인했다. `.yms`의 내부 변수/함수 79개는 해당 심볼의 주소와 일치한다.
- `.pci`의 변환 구간 65개는 `.yms`와 일치한다. 아래 행 번호는 해제한 로직 데이터의 0부터 시작하는 행이다.
- 구현에 필요한 심볼과 범위만 `tests/fixtures/52r1-protection.json`에 기록했다. 네이티브 실행 코드 전체의 역해석이나 실제 계전기 다운로드·동작 시험을 했다는 뜻은 아니다.

## 이번 적용

구간 26의 행 71~77은 아래 보호 OR와 `G86X` 출력을 포함한다.

```text
G86X = OCR50 OR OCR51 OR OCGR50 OR OCGR51 OR OVR OR UVR OR G63CB2_F
```

구간 16의 행 40~42는 수동 개방, 자동 개방, G86X의 병렬 개방 경로다.

```text
CB1_52R1_OPEN = MANUAL_52TX OR AUTO_52TX OR G86X
```

- G86X가 동작하면 52-R1을 개방하고 `G86X → CB1_52R1_OPEN` 이력을 남긴다.
- G86X가 동작 중이면 기존 투입 허가 조건에서도 재투입을 막는다.
- G86X만으로 89-R1 개방 명령을 만들지 않는다. 원본 소스의 89 개방 출력은 별도 수동/자동 변수에 연결되어 있다.
- 29X는 위 G86X 보호 OR에 포함되지 않는다. 소스에서 화재 표시·부저 경로로 전달되므로 화면에서는 경보·표시기억만 적용한다. 63G1, PTX, 29AL도 보호 트립 원인에 넣지 않는다.
- `G63CB2_F`는 가스 2단계 동작의 표시기억이다. 원인 입력을 해제한 뒤 표시기억을 복귀해야 보호 OR에서 빠진다. 반면 G86X_F 표시기억 자체를 별도의 보호 입력으로 만들지 않는다.

현재 화면의 계전 입력은 이미 동작한 내부 접점이다. 특히 `UVR` 체크는 소스 내부 UVR 출력의 직접 모의이다. 별도의 외부 UVR1·R1_84X 접점을 사용하면 아래 소스 시간 관계를 거쳐 UVR이 생성된다. 전압 정정치 자체는 계산하지 않는다.

## 명령 타이머와 보호 입력

소스의 `TON_CX`/`TON_TX` 10초는 투입·개방 명령의 유지 제한이며 보호 트립 지연으로 사용하지 않는다. RUN/TEST 순차 제어 및 LOCAL/REMOTE 경로는 아래와 같이 적용했다. 전체 전원 자동 절체와 모든 경보·부저 펄스 출력까지 재현한 PLC 에뮬레이터는 아니다.

## 검증

- 소스 보호 OR의 7개 입력을 각각 독립적으로 동작시켜 개방 출력/재투입 억제 확인.
- 29X, 63G1, PTX, 29AL은 트립·투입 억제가 발생하지 않는지 확인.
- 원인 해제와 G86X_F 표시기억, G63CB2_F의 복귀 조건을 구분하여 확인.
- 보호 트립이 89-R1 상태를 바꾸지 않는지 확인.
- 기존 AC 인터록·시간 연동 회귀 검증.

```sh
node tests/ac-protection.test.js
node tests/r1-sequence.test.js
```

## RUN/TEST 시퀀스 적용

`r1-sequence.js`는 아래 소스 접점 관계를 사용한다. 원본 데이터의 행 번호와 타이머 원문은 `tests/fixtures/52r1-sequence.json`으로 대조한다.

| 기능 | 소스 관계 / 설정 |
| --- | --- |
| 투입 피드백 | 52 a접점 → TON_52A 3초, 89 a접점 → TON_89A 1초 |
| 개방 피드백 | 52 b접점 → TON_52B 1초, 89 b접점 → TON_89B 7초 |
| CX 투입 명령 | RUN·CX_PERMIT·투입 버튼으로 시작. `CX && !TX && !TMR_52R1_A`로 유지하며 CXTMX가 끊음 |
| AUTO_89CX | `CX && DI02_52R1_B` |
| AUTO_52CX | `CX && TMR_89R1_A` |
| TX 개방 명령 | RUN·개방 버튼으로 시작. `TX && !CX && !TMR_89R1_B`로 유지하며 TXTMX가 끊음 |
| AUTO_52TX | TX |
| AUTO_89TX | `TX && TMR_52R1_B` |
| 명령 제한 | TON_CX, TON_TX 각각 10초. 정상 완료는 CB 투입 확인 3초 또는 DS 개방 확인 7초로 명령 해제 |
| TEST | CB 개별 투입·개방. 89 투입은 CB 개방 조건. 외부 DS 하드웨어 b접점 조건도 유지하며 TEST CB는 주회로에서 분리 |
| LOCAL/REMOTE | 선택된 조작 위치의 버튼 경로만 수용 |
| G27X | `DI01_52R1_A && UVR1`이 0.5초 유지되면 동작 |
| TMR_52R1_84B | **DI31_52R1_84X b접점**이므로 입력 해제 시 2초 후 동작 |
| 내부 UVR | G27X OR TMR_52R1_84B → G86X 보호 OR |

투입은 DS부터, 개방은 CB부터 동작한다. 진행 중 반대 명령, 중복 명령, 명령 시간 초과, 전체 초기화 시 지연 명령 취소를 검증한다. G86X는 RUN/TEST와 무관하게 개방 우선이다.

물리 기기는 명령 상승 에지에 즉시 응답하는 교육용 모델이다. 명령을 유지한 채 보호 트립된 차단기를 반복 재투입하지 않는다. 실패 모의는 해당 명령의 물리 응답을 없애며, 보호 트립 실패 모의는 아니다. 접점·명령/피드백과 실패 여부가 모델에 분리되어 있다. 실제 기기 이동 시간·스프링 충전·모든 기계적 인터록까지 재현하는 것은 아니다.
