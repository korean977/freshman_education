# 압축파일의 나머지 반 로직 적용

사용자가 제공한 `1.부천종합운동장변전소.zip`의 번호별 프로젝트 폴더에서 **주 파일 `.src`**를 사용했다. 이미 적용한 R1·R2·R3·52s1은 가져오기 대상에서 제외했다. `BackupForOnlineEdit*`, `.bak`, GMWIN 프로그램 폴더의 복제 프로젝트, 실행 파일과 라이브러리는 별도 설비로 취급하지 않는다. 기존 R 계열의 TEST 단로기 개방 및 89 1차측 84 검출·온수 상시 가압 조건을 유지한다.

## 적용 대상과 검증량

| 소스 | 계통도 대상 | PCI 구간 | 내부 주소 대조 |
| --- | --- | ---: | ---: |
| 52s2.src | 52-2 / 54-2 연동 | 59 | 70 |
| 52d1.src | 52-D1 | 54 | 57 |
| 52d2.src | 52-D2 | 54 | 57 |
| 52db1.src | 52-DB1 / 52-HT | 51 | 60 |
| 52db2.src | 52-DB2 | 45 | 57 |
| 52h1.src | 52-H1 / 89-H1 | 42 | 55 |
| 52h2.src | 52-H2 / 89-H2 | 45 | 69 |
| 52h3.src | 52-H3 / 89-H3 | 45 | 69 |
| 합계 | 8개 프로젝트 | **395** | **494** |

SRC의 두 PKWARE DCL 스트림에서 176바이트 심볼 레코드와 740바이트 래더 행을 복원했다. PCI의 모든 Conv 구간 시작·끝을 YMS와 대조하고, YMS 내부 변수 주소를 심볼 테이블과 대조했다. 접점 NO/NC·상승/하강 에지, 병렬 배선, 복수 코일, TON·TP·TOF 블록을 보존한 접점망을 `station-logic-data.js`로 생성한다. 각 소스의 SHA-256과 구간 행 번호가 생성 데이터에 들어 있다. 사용하지 않는 심볼 이름만으로 회로를 추가하지 않는다.

`ladder-runtime.js`는 소스 순서대로 스캔하고 `station-sequence.js`는 현장 기기 상태와 프로젝트 DI/DO를 연결한다. 명령을 누른 동안 스캔을 안정화하고 버튼을 놓은 뒤 다시 스캔한다. 타이머 시간은 실제 시간/테스트 시계를 사용하며 스캔 횟수를 시간으로 바꾸지 않는다. 모든 반의 계산 후 실제 차단기 피드백을 갱신해 DB 27TX가 같은 스캔의 H 반에 전달되게 한다. TEST 주회로는 통전 그래프에서 분리한다.

원본의 보호, 조작 허가, 표시기억, 경보·부저·운전 위치 DO까지 실행한다. 주요 접점은 한국어 모의 입력으로 제공하고 나머지 원본 접점(CC 시험 접점, 보호요소 다른 단계, 진단·예비 접점 등)은 ‘추가 원본 접점 모의’에서 제공한다. FRESET은 표시기억 복귀 버튼으로 동작한다. 동작 중인 원인이 있으면 복귀 후 다시 자기유지된다. ‘원본 출력·허가 접점’에서 DO/PO/CB 및 허가 상태를 볼 수 있다.

## 회로별 차이

- **52-2:** 출력 이름 `CB1_52S1_CLOSE/OPEN`이 남아 있지만 이 프로젝트의 실기기 매핑은 **52-2**이다. 52-1을 조작하지 않는다. RUN 투입 `NEG_A && HSCB_B && !G86X`, 수동 개방 HSCB_B, TEST 우회 및 TRIP_TEST1을 적용한다. HSCB 고장의 TP는 즉시 시작하여 1초 유지하고, 입력이 계속 ON이어도 재트리거하지 않는다. DO14 허가·DO15 트립은 54-2와 연결한다. S1과 달리 G86X_F와 REC_FAULT_F도 이 소스 그대로 계산한다.
- **D1·D2:** RUN 투입은 해당 DB 개방 및 G86X 비동작, RUN 수동 개방은 DB 개방. TEST는 수동 허가를 우회하되 보호·시험 개방이 우선한다. OCR1_50/51, OCGR1_50/51, DFR_F, G63CB_TP2_F, **생입력 DTR_26TP**가 자체 FAULT와 G86X를 만든다. DTR_26TP 표시기억 자체는 보호를 유지하지 않는다. 87T와 63G2는 `_F`가 보호 입력이다. 이전 PDF 해석의 화재 트립을 제거했고, 29AL은 경보로 처리한다. DB 고장과 R1 27X 수신은 표시만 한다.
- **D→DB:** D1 `DO14_52D1FAULT`, D2 **`DO14_D2FAULT`**를 각각 DB의 DI22 고장 수신에 연결한다. 두 출력은 `_FAULT_F`에서 나오므로 표시 복귀 전까지 유지된다. DB의 수신 분기는 상승 에지→**500ms TP**이며, 유지된 고장 입력을 무한 트립으로 바꾸지 않는다. D 출력 이름의 차이를 보존했다.
- **DB1·DB2:** RUN 허가 `D_A && (!HT_A || !반대쪽_DB_A)`. 이전 HT 투입 중 미확인 분기 보류를 해제했다. 이 허가 자체에는 G86X b접점이 없다. 보호가 활성화된 경우 원본 개방 출력이 투입보다 우선한다. `UVR1 && DB_A`의 0.5초 TON→G27T→G27TX와 CC3 시험 분기를 적용한다. OCR50/51은 자기 보호 및 upstream FAULT 출력, 64T/OVGR은 경보·표시기억만 만든다.
- **HT:** DB1의 CB2 LOCAL/REMOTE 조작 경로. RUN 허가는 DB1·DB2 중 하나 이상 개방. 소스의 RUN/TEST 허가 분기는 **DB1 위치**를 사용하고 HT 자체 위치 접점은 위치 표시 출력에 사용한다. HT 화면의 위치는 HT 주회로 연결 여부이고 LOCAL/REMOTE는 DB1과 공유한다. TRIP_TEST2는 HT만 개방한다. DB1의 G86X를 HT 보호로 추가하지 않는다.
- **H1·H2·H3:** RUN 허가 `89_A && !DB_27TX && UVR1 && !G86X`. **원본은 UVR1 a접점**이므로 ON이 투입 허가 조건이다. 기존 PDF 기반 UVR1 b접점 추정을 교체했다. UVR1 단독 트립은 없다. OCR50/51, DR_GR_F와 해당 DB 27TX가 보호를 만든다. H1은 DB1 27TX의 **1초 TOF**를 사용하여 입력 해제 후에도 1초 유지한다. H2는 DB1, H3는 DB2의 생입력으로 즉시 동작한다. 이 세 소스에 없는 TRIP_TEST1을 추가하지 않는다.
- **H 단로기:** H1 RUN 단로기 투입은 H1 개방 조건이고 소스 개방 출력은 별도 명령이다. 기존에 도면에서 확인한 H1 외부 단로기 인터록(차단기 개방 중 조작)을 유지한다. H2·H3 RUN 단로기 투입은 차단기와 **동일 CX_PERMIT**을 사용하므로 최초 투입은 TEST에서 한다. H2·H3의 별도 외부 인터록은 소스에서 확인되지 않아 다른 반의 조건을 복제하지 않았다.

## 재생성과 테스트

`zlib/contrib/blast`의 `blast.c`·`blast.h`로 공유 라이브러리를 만들고 다음을 실행한다. GMWIN 실행 파일은 실행하지 않는다.

```sh
cc -O2 -shared -fPIC blast.c -o /tmp/libblast.so
python3 scripts/import_gipam_logic.py /path/to/extracted-parent --blast-library /tmp/libblast.so --output /tmp/station-logic-data.js
cmp station-logic-data.js /tmp/station-logic-data.js
node tests/station-sequence.test.js
```

검증은 D/DB/H 투입 허가 및 LOCAL/REMOTE·RUN/TEST 분기의 진리표, H2/H3 복수 출력 분기, 모든 D·S2 보호 원인, DB 499/500ms·H1 TOF 999/1000ms·S2 TP 999/1000ms 경계, 짧은 입력 취소·재입력·자기유지 복귀, 양쪽 계통 연동, HT CB2 경로, 출력 명칭 매핑, 경보 펄스·10초 부저 및 전역 초기화를 포함한다. 기존 여섯 테스트 파일도 함께 실행한다. 브라우저에서는 새 9개 조작 패널을 320·390·768·1440px에서 확인한다.

배포에는 웹용으로 변환한 접점망과 JS/CSS/HTML만 포함한다. ZIP·프로젝트 원본·PDF·제조사 프로그램·생성 도구는 사이트에 배포하지 않는다. 이 압축파일의 설비 프로젝트는 AC 12개 반이며 별도의 DC 차단기 자체 로직은 없다. 따라서 54-1·54-2의 AC 허가/트립 연동 외 DC 보호 정정치를 생성하지 않는다. 보호 입력은 이미 동작한 접점이며 아날로그 전류·전압 정정값이나 실기기 통신을 실행하는 모델이 아니다.
