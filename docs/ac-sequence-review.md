# AC 시퀀스 1차 적용 기록

대상은 운전(RUN) 상태에서의 확인된 투입 허가, 수동 개방 제한, 보호 접점 입력 및 명시된 일부 연동이다. 제어전원/스프링이 정상인 교육 조건이다. TEST 우회, LOCAL/REMOTE 선택, 자동 절체·순차 조작, 기계적 인터록, 정정치/전류·전압 계산, 전체 DC 보호는 구현하지 않았다.

`ac-protection.js`의 입력은 이미 동작한 계전 출력 접점이다. 따라서 OCR51 체크가 바로 반응하는 것은 정정 시간을 0초로 설정했다는 뜻이 아니다. 도면의 500 ms `TP_OCR50`, `TP_OCR51` 등은 경보 출력 쪽 펄스이며 보호요소의 동작 시간으로 쓰지 않았다.

도면 PDF 17개와 52r1 프로젝트 파일을 검토했으나 원본은 저장소에 게시하지 않았다. 아래 파일명은 사용자가 제공한 원본을 가리킨다. 각각 1페이지다.

## 표시기억과 원인 신호

- 화면의 표시기억은 동작 사실을 남긴다. 일반 OCR 원인이 해제되어 86X가 떨어진 경우, 남은 표시기억 자체를 별도 86X 잠금으로 사용하지 않는다.
- 보호 OR에서 `_F` 접점을 직접 사용하는 항목은 원인 입력을 해제한 뒤 표시기억까지 복귀해야 허가가 회복된다. 적용 항목: R1의 63G2, D1의 87T/29X/63G2, H1의 SGR, 52-1의 63G2.
- 원인이 동작 중이면 해당 설비의 일괄 표시기억 복귀를 허용하지 않는다. 전역 초기화는 모든 설비를 초기 상태로 돌리고 모의 입력·표시기억·대기 타이머도 지운다.
- 외부 84X 입력은 기본 비동작, 도면 밖 NEG a접점은 기본 투입 상태인 연습용 초기값이다. 실제 현장 상태를 의미하지 않는다.

## 확인이 필요한 경로

1. **DB1 CX1 PERMIT 우측 병렬 분기:** DI13 `52DB2_A` 및 DI03 `52HT_A` 표기와 되돌아가는 접속선에 해석상 불확실성이 있다. HT 개방 시의 직접 경로만 허용하고, HT 투입 중 DB1 투입은 '도면 확인 필요'로 보류한다. 흔히 쓰이는 일반적인 2-out-of-3 회로를 추정해 대신 넣지 않았다.
2. **52S1 DI35:** 상단 입력 표기는 HSCB_A인데 CX PERMIT에서는 HSCB_B로 기재되어 있다. 54-1 개방인 확인 가능한 상태에서만 RUN 투입을 허용하고, 54-1 투입 중 경로는 보류한다. 수동 개방 회로의 DI36 HSCB_B는 별도로 확인된다.
3. **D1 TR26TP와 DB1 FAULT:** 입력·표시 경로는 있으나 제공된 G86X 보호 OR에 직접 들어가는 접점은 보이지 않는다. 임의로 자동 트립 원인에 넣지 않았다.
4. **DB1 64T/OVGR:** CC4 및 표시 경로는 확인되지만 86X 보호 OR에는 보이지 않는다. 표시만 적용했다.
5. **R1 자동 순차 조작/84X 타이머/27X 송출:** 일부 타이머와 신호가 있으나 전체 자동 절체 동작은 이번 범위에서 제외한다. 소스로 확인한 G86X 보호·개방 경로를 적용했다. 전체 자동 순차 동작은 아직 소스와 동등하다고 주장하지 않는다. 상세는 [52r1 소스 적용 범위](52r1-source-logic.md)를 참조한다.
6. **반대쪽 2호계 및 R2/R3:** 해당 시퀀스가 없으므로 보호조건을 복제하지 않았다. 기존 단순 조작만 가능하고 화면에 도면 미등록으로 표시한다. 미등록 기기를 통한 전체 설비 인터록까지 검증되었다고 볼 수 없다.

## 검증

```sh
node tests/ac-protection.test.js
```

정방향/역방향 인터록, 보호 트립의 수동 제한 우회, D1→DB1 전파, 역방향 경보, H1 DS 조건, 소스 기준 R1 트립·경보 구분 및 R2/R3 84X 진리표, 0.5초/1초 타이머와 취소, 원인 해제/표시기억 복귀 및 초기화 후 지연 동작 방지를 검증한다. UI는 상대 경로로 JS/CSS를 읽으며 GitHub Pages와 다운로드한 정적 파일 모두 사용 가능하다.
