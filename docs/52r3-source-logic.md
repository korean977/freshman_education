# 52-R3 프로젝트 소스 적용

사용자가 제공한 `52r3.src`를 기준으로 시퀀스와 보호·투입 허가를 구현했다. 원본 PRJ/SRC/PCI/YMS/BAK/LOG는 저장소나 배포 사이트에 게시하지 않았다.

## 파일 대조

- SRC 헤더: `LGIS PADT V0.11a SRC / G2K_FI SOURCE`.
- PKWARE DCL 압축을 공식 zlib contrib/blast로 해제했다. 심볼 블록 28,336바이트(176바이트 × 161개), 로직 블록 130,980바이트(740바이트 × 177행).
- YMS 내부 변수·함수 74개의 주소가 소스 심볼과 일치한다. PCI 변환 구간 59개도 YMS와 일치한다.
- BAK의 해제한 로직 블록은 SRC와 일치한다. LOG는 과거 연결·모니터 기록으로, 현재 현장 장치의 버전을 보증하지 않는다.
- `tests/fixtures/52r3-sequence.json`에 검토한 타이머·보호 분기·투입 허가 분기를 기록했다.

## 시퀀스

| 기능 | 소스 근거 | 적용 |
| --- | --- | --- |
| CB 투입/개방 확인 | 행 27/30: TON_52A / TON_52B | 3초 / 1초 |
| DS 투입/개방 확인 | 행 33/36: TON_89A / TON_89B | 1초 / 7초 |
| 투입 제한 | 행 59: TON_CX T#8S | 8초, R1의 10초와 구분 |
| 개방 제한 | 행 70: TON_TX T#10S | 10초 |
| RUN 투입 | CX → AUTO_89CX → TMR_89R3_A → AUTO_52CX → TMR_52R3_A | 89-R3 투입 → 1초 → 52-R3 투입 → 3초 확인 |
| RUN 개방 | TX → AUTO_52TX → TMR_52R3_B → AUTO_89TX → TMR_89R3_B | 52-R3 개방 → 1초 → 89-R3 개방 → 7초 확인 |
| TEST | 행 53~56, 64~67 | 개별 CB/DS 명령과 LOCAL/REMOTE 경로. TEST CB는 주회로 가압 계산에서 분리 |

R1/R2와 타이머·출력·설정을 독립 유지한다. 명령 출력의 상승 에지에 응답하는 교육용 물리 모델이며 명령 응답 실패를 모의할 수 있다. 자기유지 중 허가 변화, 반대 명령, 반복 명령, 보호 우선, 제한 시간과 전체 초기화의 지연 동작 취소를 공통 엔진으로 처리한다.

## 투입 허가

소스 구간 19, 행 47~51의 접점 종류와 연결 비트로 복원한 병렬 경로는 아래와 같다. `!`는 b접점, `&&`는 직렬이다. 각 경로 뒤에 G86X b접점이 공통 직렬 연결된다.

```text
!R3_84X && !R1_A && R2_A
!R3_84X && R1_A
!R3_84X && !R1_A && !R2_A
 R3_84X && !R1_A && !R2_A
 R3_84X && !R1_A && !R2_84X && R2_A
```

정리한 식:

```text
CX_PERMIT = !G86X && (!R3_84X || (!R1_A && (!R2_A || !R2_84X)))
```

압축 해제한 원본 접점·배선의 연결 그래프를 32개 입력 조합으로 이 식과 대조했다. 커밋한 테스트도 5개 분기를 기준으로 구현과 실제 명령 허가 결과를 대조한다. R3는 자신의 84X가 동작할 때 R1 개방 및 R2 개방 또는 R2 84X 비동작이 필요하다.

R2_84X와 R3_84X는 세 반에서 동일한 수동 외부 입력을 공유한다. R3 적용에 맞춰 두 입력 모두 초기 true로 두었다(R3는 종전 false에서 변경). R1의 84X 정상 접점도 초기 true지만 R1 UVR 타이머용 별도 신호다. 이는 실제 현장 상태를 읽는 것이 아닌 연습용 초기값이다. 세 차단기의 실제 투입·개방 상태와 각 프로젝트 허가식을 연결하며 전체 자동 절체를 추가하지 않았다.

## 보호와 표시

소스 구간 26, 행 74~79와 구간 16, 행 40~42:

```text
G86X = OCR50 OR OCR51 OR OCGR50 OR OCGR51 OR OVR OR G63CB2_F
CB1_52R3_OPEN = MANUAL_52TX OR AUTO_52TX OR G86X
```

- 위 6개 분기가 R3 자동 트립과 재투입 억제를 만든다. 다른 반을 직접 트립시키지 않으며 G86X만으로 89-R3를 자동 개방하지 않는다.
- 63G2_F는 원인 입력 해제와 표시기억 복귀가 필요하다. 일반 OCR의 표시기억을 별도 잠금으로 추가하지 않았다.
- UVR1은 UVR1X와 DO04_UVR_AL(행 133)의 표시·경보 경로다. G86X OR에는 없어 트립·투입 억제를 만들지 않는다. R1의 27X/84X UVR 타이머도 R3에는 없다.
- 63G1·PTX·29AL은 표시·경보만 적용한다. 심볼에만 남은 DI32_29X에서 화재 트립을 추정하지 않았다.
- R3 경보 출력은 R2와 달리 DO01에 OCR50, DO21에 OCR51의 개별 500ms 펄스가 있다(행 123~125, 141~143). 이 시간은 보호요소 동작 지연으로 사용하지 않는다. 모든 경보 펄스·부저·스페어 출력을 재현하는 PLC 에뮬레이터는 아니다.

## 확인된 TEST 단로기 동작

소스 TEST `MANUAL_89CX`에는 CB a접점의 반전 조건이 있고 `MANUAL_89TX`에는 없다. 따라서 TEST에서 CB 투입 중 DS 개방 명령을 주면 `PO01_89R3_OPEN` 출력은 이력에 기록한다. 사용자는 R3의 TEST에서는 CB 투입 중에도 DS 개방이 가능하다고 확인했다. 따라서 이 출력으로 89-R3가 실제로 개방되는 교육용 응답을 적용했다. TEST DS 투입은 소스의 CB 개방 조건을 유지하고, RUN 개방 순서도 CB → DS로 유지한다. 사용자는 R1/R2도 동일하게 TEST에서 CB 투입 중 단로기 개방이 가능하다고 확인했다. 세 프로파일 모두 이 동작을 적용하며 TEST 투입 제한과 RUN 순서를 회귀 테스트로 구분한다.

## 검증

```sh
node tests/ac-protection.test.js
node tests/r1-sequence.test.js
node tests/r2-sequence.test.js
node tests/r3-sequence.test.js
python3 scripts/build_site.py
```

RUN/TEST, LOCAL/REMOTE, 투입 8초/개방 10초, 6개 보호 분기, UVR1 비트립, 가스압력 자기유지, 32개 투입 허가 조합, 세 반의 84X 공유·상호 허가, 독립 타이머, 명령 응답 실패·중단·초기화를 검증한다. 단선계통의 한전 1전원 모델과 원본 PNG는 유지한다.
