# 52-R2 프로젝트 소스 적용

사용자가 제공한 `52r2.src`를 기준으로 시퀀스와 보호·투입 허가를 구현했다. 원본 PRJ/SRC/PCI/YMS/BAK/LOG는 저장소나 배포 사이트에 게시하지 않았다.

## 파일 대조

- SRC 헤더: `LGIS PADT V0.11a SRC / G2K_FI SOURCE`.
- PKWARE DCL 압축을 공식 zlib contrib/blast로 해제했다. 심볼 블록은 28,160바이트(176바이트 × 160개), 로직 블록은 132,460바이트다.
- YMS 내부 변수·함수 73개가 소스 심볼과 주소까지 일치한다. PCI의 변환 구간 58개도 YMS와 일치한다.
- BAK의 해제한 로직 블록은 SRC의 해당 블록과 일치한다. 이것만으로 현장 장치에 같은 버전이 적용되었음을 뜻하지는 않는다.
- `tests/fixtures/52r2-sequence.json`에 필요한 타이머·보호 분기·허가 분기만 기록했다.

## 시퀀스

| 기능 | R2 소스 | R1과 구분 |
| --- | --- | --- |
| CB 투입/개방 확인 | TON_52A 3초 / TON_52B 1초 | 동일한 시간값이지만 접점과 상태는 R2에 독립 연결 |
| DS 투입/개방 확인 | TON_89A 1초 / TON_89B 7초 | R2의 89-R2 피드백 사용 |
| 투입 명령 제한 | **TON_CX 8초** (소스 행 59) | R1은 10초 |
| 개방 명령 제한 | TON_TX 10초 (행 70) | R1과 시간값은 동일 |
| RUN 투입 | CX → CB b접점에 따라 AUTO_89CX → DS 투입 1초 확인 → AUTO_52CX → CB 투입 3초 확인으로 유지 해제 | R2의 CX_PERMIT을 적용 |
| RUN 개방 | TX → AUTO_52TX → CB 개방 1초 확인 → AUTO_89TX → DS 개방 7초 확인으로 유지 해제 | CB부터 개방 |
| TEST | 개별 CB/DS 명령, LOCAL/REMOTE 선택 경로 | TEST CB는 주회로에서 분리 |
| 물리 응답 | 출력 상승 에지에 응답하는 교육용 모델, 명령 응답 실패 모의 지원 | 보호 트립 실패 모의가 아님 |

CX와 TX 자기유지 분기는 시작 명령의 RUN/허가 조건과 구분한다. 초기 허가 변화만으로 이미 시작된 코일의 유지 분기를 임의로 끊지 않는다. 진행 중 반대 명령, 반복 명령, 시간 초과, 전체 초기화의 지연 명령 취소를 검증했다.

## 투입 허가

소스 구간 19, 행 47~51의 접점 종류(a/b)와 연결 비트를 대조했다. G86X b접점 앞에는 다음 5개 병렬 경로가 있다. `!`는 b접점, `&&`는 직렬이다.

```text
!R2_84X && !R1_A && R3_A
!R2_84X && R1_A
!R2_84X && !R1_A && !R3_A
 R2_84X && !R1_A && !R3_A
 R2_84X && !R1_A && !R3_84X && R3_A
```

이를 정리하면 다음과 같다.

```text
CX_PERMIT = !G86X && (!R2_84X || (!R1_A && (!R3_A || !R3_84X)))
```

소스 접점·배선 비트의 연결 그래프와 위 식을 32개 입력 조합으로 대조했고, 커밋된 테스트는 원본의 5개 분기와 구현을 다시 대조한다. R1의 투입 허가를 이름만 바꾸어 복사하지 않았다.

R2 자신의 84X와 R3의 84X는 R1/R2/R3에서 같은 외부 접점을 나타내므로 입력을 공유한다. R2_84X는 연습 초기값을 true로 두고 R1 화면에도 같은 값이 표시된다. R3 적용 이후 R3_84X도 초기 true이며 세 반에서 공유한다. 실제 현장 신호를 읽는 것은 아니다.

## 보호와 표시

소스 구간 26, 행 74~79:

```text
G86X = OCR50 OR OCR51 OR OCGR50 OR OCGR51 OR OVR OR G63CB2_F
CB1_52R2_OPEN = MANUAL_52TX OR AUTO_52TX OR G86X
```

- 위 6개 분기가 R2 트립과 재투입 억제를 만든다. 63G2_F는 원인 입력을 해제한 뒤 표시기억을 복귀해야 해제된다.
- **UVR1은 R2의 G86X 보호 OR에 없다.** UVR1X 표시/경보 경로를 적용하며 R1의 0.5초/84X 2초 UVR 보호를 복사하지 않았다.
- 63G1, PTX, 29AL도 표시·경보만 적용한다. DI32_29X는 심볼에 있지만 이 프로젝트의 해당 제어·보호 경로에 사용되지 않아 R2 화재 트립 기능을 만들지 않았다.
- R2의 트립이 R1의 차단기·단로기를 직접 움직이거나 R1 보호를 동작시키지 않는다.

## 확인된 TEST 단로기 동작

프로젝트의 TEST `MANUAL_89CX`에는 CB a접점의 반전 조건이 있지만 `MANUAL_89TX`에는 같은 조건이 없다. 사용자는 R1/R2/R3 모두 TEST에서 CB 투입 중 단로기 개방이 가능하다고 확인했다. 따라서 TEST 개방 명령은 `PO01_89R2_OPEN` 출력을 기록하고 89-R2를 실제로 개방하는 교육용 응답을 만든다. TEST 단로기 투입은 여전히 CB 개방이 필요하며, RUN 개방은 CB → 1초 확인 → DS 순서를 유지한다.

## 검증 및 경계

```sh
node tests/ac-protection.test.js
node tests/r1-sequence.test.js
node tests/r2-sequence.test.js
```

RUN/TEST, 8초·10초 제한, G86X 6개 분기, UVR1 비트립, 84X 공유, R1/R2 상호 허가, 독립 타이머·설정, 실패·중단·초기화, 확인된 TEST DS 개방 허용·투입 제한을 검증한다. 전체 전원 자동 절체나 모든 부저·표시 출력 펄스를 재현하는 PLC 에뮬레이터는 아니다. 기존 단선계통의 한전 1전원 연결 모델은 유지한다.
